# 《回响特攻》ECHO RUSH 中文开发计划书

版本：1.0｜日期：2026-10-26｜目标：单人开发、PC 与手机横屏可玩、GitHub 托管、Render Static Site 发布。

本文是待实现的设计与执行合同，不代表游戏已经开发或测试完成。原对话中的助手内容仅能读取到引用占位；以下以本次明确需求为依据补齐规则。所有数值均为首轮调试起点，实测后集中修改配置，不作为已经验证的平衡结论。

## 1. 项目定位与交付边界

一句话玩法：**你在当前6秒躲避并输出，过去最多3段6秒行动变成自动循环的分身；通过走位布置未来火力，再把当前敌人引入历史弹道。**

类型：固定竞技场、俯视角、自动射击、短局生存。每局180秒，存活至结束即胜利，死亡立即失败。研究深度集中在动作记录、事件回放、统一战斗结算与工程验证，不通过堆系统增加工作量。

### 1.1 首个完整版本必须有

- 一个无内部障碍、无滚动镜头的矩形竞技场。
- 一名玩家、一种基础枪、冲刺与震荡波两个主动技能。
- 6秒记录、最多3个循环分身、清晰的循环进度与分身来源提示。
- 追击者、冲锋者、射击者三种普通敌人。
- 三个60秒强度段；60秒和120秒各一次暂停式三选一升级。
- 开始、暂停、胜败结算、重开、音量与减少特效设置。
- PC 键盘、手机多点触控、竖屏暂停提示、失焦暂停。
- 核心逻辑测试、浏览器交互检查、真实手机验证、静态部署说明。

### 1.2 明确延后

不做联网、账号、云存档、在线排行、后端、数据库、AI模型、关卡编辑器、随机地图、障碍物寻路、装备背包、复杂技能树、Boss、物理推箱子、分身受伤或仇恨、分身复制分身。首版也不做手动瞄准模式、倍速、慢动作和时间倒流。

美术先用程序绘制几何图形；完成 M5 的核心趣味验证后再改善表现。首版不依赖外部素材 CDN、付费资源或在线接口。

### 1.3 完成标准

新用户进入公开网址，点击开始，能在PC或手机横屏完成一局并重开；6秒机制能看懂，暂停恢复不乱序，无持续增长的对象和监听器，构建与关键测试通过。公开网址和真实设备结果未核验前，只能称为“本地完成”或“部署待验证”。

## 2. 玩家体验与核心决策

### 2.1 操作

| 动作 | PC | 手机横屏 |
| --- | --- | --- |
| 移动 | WASD / 方向键 | 左侧虚拟摇杆 |
| 基础攻击 | 自动瞄准并射击最近敌人 | 同PC |
| 冲刺 | Space | 右侧冲刺按钮 |
| 震荡波 | Q | 右侧震荡波按钮 |
| 暂停 | Esc / 页面暂停按钮 | 页面暂停按钮 |

不要求持续按住开火。自动瞄准只用于真人的当次攻击；分身只使用录制方向，不重新锁定目标。移动输入归一化，斜向速度不增加；摇杆死区0.15，超出外圈截断到1。

### 2.2 一局节奏

1. 0～6秒：玩家独自移动与射击，建立第一条轨迹。
2. 6秒：第一分身出现，重复刚才行动。玩家开始把追击者引入旧火线。
3. 12秒、18秒：形成两条、三条历史轨迹。
4. 24秒以后：始终保留最近三段完整记录。玩家必须持续更新布置，无法永久保留一次完美轨迹。
5. 60秒、120秒：暂停选升级，继续同一战场；敌人、弹丸与血量保留。
6. 180秒：存活即胜利；展示总击杀、真人伤害、分身伤害、分身命中率与局内用时。

主要策略是“当前生存”和“下一轮布阵”的取舍：绕圈稳定但火线分散；短距离往返能覆盖走廊但增加真人受伤风险；震荡波可以留下周期性清场区域；站桩火力集中但会被冲锋与远程敌人压制。

### 2.3 可读性

真人白色实心、分身青色半透明、敌人橙红；除颜色外，用实心/轮廓、编号与形状区分。分身标记为最近、较早、最早，不让固定颜色暗示固定能力。HUD显示“本段 3.2 / 6.0秒”“分身 2 / 3”。

循环前0.5秒显示收束弧线；切换时仅轻量闪烁，分身在旧起点重新出现。回放瞬移处不绘制跨场伤害线。允许设置关闭闪光、震屏、密集残影。

玩家与敌人均限制在竞技场内，敌人之间可重叠；首版不做互相推挤。玩家不会被敌人卡住，危险来自接触伤害和弹幕。生成点距玩家至少220，边缘预警36 tick后激活，预警期间不可被命中、不阻挡弹丸。最多尝试16次候选点，无合格点则跳过该次生成。

## 4. 6秒记录与分身循环：不可歧义的规则

### 4.1 记录的是结果，不是键盘历史

每个仿真 tick记录真人**完成移动和边界限制后的世界位置、朝向、冲刺状态**，以及该 tick **成功发出的攻击事件**。不通过重放键盘输入重新计算分身移动，不记录整个世界、敌人位置、伤害结果或目标对象引用。

理由：敌人世界已经变化，按输入重算容易受新碰撞和状态影响。位置轨迹回放可以精确复现真人走位，而攻击仍然与当前世界真实碰撞。

分身是“历史运动轨迹 + 历史攻击发射器”，不是完整世界回滚，也不是会重新思考的AI队友。

### 4.2 唯一计时源

`completedTicks` 初始0。每执行一完整步后加1；`localTick = completedTicks % 360` 在该步开始时计算，范围0～359。该步的所有记录都使用这个localTick。

| 已完成步数 / 仿真时刻 | 新封存记录 | 下一步将回放的记录（旧→新） |
| --- | --- | --- |
| 0 / 0秒 | 无 | 无 |
| 360 / 6秒 | C0：第0～359步 | C0 |
| 720 / 12秒 | C1：第360～719步 | C0、C1 |
| 1080 / 18秒 | C2 | C0、C1、C2 |
| 1440 / 24秒 | C3 | C1、C2、C3；淘汰C0 |
| 1800 / 30秒 | C4 | C2、C3、C4；淘汰C1 |

一段覆盖半开区间 `[0,6秒)` 的360次动作步。索引0是起点经过第一步移动后的姿态；`startPose` 是该段第一步之前的姿态。索引359存第360步结束姿态。新分身在封存后渲染于 `startPose`，从下一步的索引0开始移动和发射，绝不在生成时额外执行一次索引0事件。

### 4.3 所有分身共用同一相位

每次6秒边界，所有保留分身回到各自记录的 `startPose`，事件游标重置；新分身加入；下一仿真步所有分身都播放localTick 0。每个分身一直循环自己那段记录，直到被新记录淘汰。每个分身每轮最多回放360步。

第4段不是第4个同时活动分身。边界操作原子完成：封存真人记录 → 若已有3个则释放最旧播放实例 → 创建新播放实例 → 重置全部播放游标 → 为真人开启下一段。渲染与攻击系统看不到4个活动分身的中间状态。

### 4.4 世界不重置

分身回到历史起点时，真人、敌人、血量、技能冷却、分数和存活弹丸保持当前值。真人不会被拉回过去；敌人不会复活。分身可与真人及彼此完全重叠，不阻挡攻击、不吸引仇恨、不受伤。

已发出的弹丸具有独立实例和有限寿命：即使来源分身被淘汰，也继续飞至命中、出界或寿命耗尽。实例持有完整伤害快照与来源ID，不需要读取已经销毁的分身或记录。清空旧分身时不清空它的在途弹丸，避免边界吞伤害。

### 4.5 不完整记录

玩家在不足6秒时死亡：本段丢弃，不生成短片段、不补零、不结算死亡后的攻击。手动退出和重开也清空当前段。暂停、升级选择、手机竖屏提示不会封存或截断记录，只冻结进度。胜利到达180秒时直接结算，不生成下一段的分身。

## 5. 数据结构与序列化合同

以下代码用于明确接口，不要求M0一次实现。核心类型放 `src/core/types.ts`，不导入Phaser、DOM、Sprite或物理Body。

```ts
type EntityId = number; // 一局内单调递增，不复用
type ClipId = number;
type Vec2 = Readonly<{ x: number; y: number }>;

interface PoseSample {
  readonly x: number;
  readonly y: number;
  readonly aimRad: number; // 世界朝向；角度插值走最短弧
  readonly dashing: boolean;
}

interface ProjectileSnapshot {
  readonly damage: number; // 发射时真人最终整数伤害，尚未乘分身系数
  readonly speed: number;
  readonly radius: number;
  readonly ttlTicks: number;
}

type RecordedAttack =
  | Readonly<{
      kind: 'shot';
      seq: number; // clip内单调递增，0起；不是数组下标约定
      localTick: number; // 0..359
      origin: Vec2; // 发射口的世界位置，已经完成边界夹取
      angleRad: number;
      projectile: Readonly<ProjectileSnapshot>;
    }>
  | Readonly<{
      kind: 'shockwave';
      seq: number;
      localTick: number;
      origin: Vec2;
      radius: number;
      damage: number;
    }>;

interface EchoClip {
  readonly schemaVersion: 1;
  readonly clipId: ClipId;
  readonly startCompletedTick: number;
  readonly durationTicks: 360;
  readonly startPose: Readonly<PoseSample>;
  readonly poses: ReadonlyArray<Readonly<PoseSample>>; // 恰好360个
  readonly events: ReadonlyArray<RecordedAttack>; // 按tick、seq排序
}

interface EchoPlayback {
  id: EntityId;
  clipId: ClipId;
  loopSerial: number; // 本播放实例的轮次，重播时递增
  eventCursor: number;
  previousPose: PoseSample;
  pose: PoseSample;
}

type AttackSource =
  | Readonly<{ kind: 'player'; entityId: EntityId }>
  | Readonly<{ kind: 'enemy'; entityId: EntityId }>
  | Readonly<{
      kind: 'echo'; entityId: EntityId; clipId: ClipId;
      loopSerial: number; eventSeq: number;
    }>;

interface AttackInstance {
  id: EntityId;
  source: AttackSource;
  damage: number; // 已在构造时完成分身缩放
  createdAtTick: number;
}

interface InputCommand {
  moveX: number; // [-1,1]，后续向量长度≤1
  moveY: number;
  dashPressed: boolean; // 一次边沿指令，消费后清除
  shockwavePressed: boolean;
}
```

### 5.1 录制器与播放器职责

- `EchoRecorder`：持有可变构建缓冲，追加真人姿态和已提交攻击，满360步后校验并封存。
- `EchoManager`：持有最多3份封存clip及其播放实例；分配ID、FIFO淘汰、边界重置。
- `EchoPlayback`：只读clip，不写clip；按localTick赋值姿态，读取该tick的事件并交给攻击工厂。
- `AttackFactory`：为真人与分身创建新攻击实例；仅分身入口应用0.45系数。
- `DamageSystem`：统一处理实际命中、去重、死亡与统计，不写录制器。

一个方向是 `真人已提交攻击 → 录制器`；另一个方向是 `clip事件 → 新攻击实例`。禁止把攻击工厂产生的所有事件广播回录制器，否则出现“分身录分身”的指数增长。

### 5.2 快照与内存

封存时复制构建缓冲并递归冻结（开发环境）；TypeScript的readonly不能代替运行时不可变约束。后续升级只修改真人属性，不能改旧clip。每次回放从快照创建新实例，不复用旧弹丸ID。

始终仅保留3份clip + 1份当前记录，即最多1440个姿态样本；每段事件硬上限256。基础枪只有30次/段，震荡波至多2次/段，保留充足余量。触达事件上限则拒绝该次新攻击，同时不消耗技能冷却，并写开发计数；正式平衡不应接近该上限。

姿态首版用普通对象数组，易调试；不要为了不足千级样本先引入压缩、二进制协议或TypedArray。内存实际值要测，不能把原始浮点字节数当成JavaScript对象真实占用。JSON导出只作为开发夹具，不提供玩家导入文件功能。

## 6. 仿真顺序与6秒边界算法

### 6.1 固定步长

Phaser负责渲染、场景、资源、输入和声音；纯TypeScript核心负责位置、战斗、计时和回放。首版**不启用Arcade/Matter作为战斗权威**，避免Phaser自动物理步和自定义仿真各自更新一次。

渲染帧delta只交给一个累加器，每步固定 `1000/60 ms`。普通帧最多接纳100ms、执行6步；若单帧间隔大于250ms，进入性能暂停并等待用户继续，不补算这段空白。100～250ms的间隔截断到100ms，属于明确的游戏时间减速；HUD与循环都只使用completedTicks，不追赶墙钟。

为便于比较不同帧率，提供 `advanceElapsed(ms)` 和 `step(command)`：无超时截断时，30/60/120Hz应推进同样的仿真步。浮点累加器做小容差处理并测试，不用 `Date.now()` 决定封存时间。

```text
一完整步（仅RUNNING允许）：
  1. 读取并消费InputCommand；localTick = completedTicks % 360。
  2. 按配置生成/激活敌人，更新敌人AI、预警、速度和位置。
  3. 处理真人技能意图、移动和竞技场边界；得到本步真人pose。
  4. 各分身读取poses[localTick]；禁止从上一轮终点扫到本轮起点。
  5. 真人选目标并提交射击/震荡波；分身提交该tick的已录事件。
     先检查容量；接受的真人攻击才开始冷却、写入录制器。
  6. 更新友方/敌方弹丸，执行连续碰撞；震荡波做瞬时范围判定。
  7. 收集伤害，按统一规则结算死亡、击杀和真人受伤。
  8. 录制真人本步pose；回收失效实体；completedTicks += 1。
  9. 若真人死亡：DEFEAT；不再执行下面任何边界操作。
 10. 若completedTicks == 10800：VICTORY；不再生成分身。
 11. 若completedTicks % 360 == 0：封存、淘汰、加入、重置、开启新段。
 12. 若completedTicks是3600或7200：进入UPGRADE，等待选择。
```

同tick击杀敌人不会撤销该敌人本步已经提交的攻击或接触候选，以“本步开始时存活且满足攻击条件”的快照判定。真人同tick归零与到达180秒同时发生时，死亡优先。击杀先标记再统一移除，避免遍历时删除元素导致漏判。

### 6.2 冷却与并发输入

使用 `nextAllowedTick`，只有当前绝对tick达到它才可施放；成功时设为 `currentTick + cooldownTicks`。不在分身重播时计算技能冷却。真人冲刺与震荡波同tick按下时，冲刺优先，震荡波请求丢弃；冲刺期间不射击、不放震荡波，枪冷却不重置。冲刺路径仅限制到场地边界，没有内部障碍。

冲刺按下瞬间优先使用移动方向，否则使用最后有效朝向。所有动作按下采用边沿触发，长按技能不会每步重复触发；一显示帧补算多步时，只在第一步消费按下指令，移动状态可以持续。移动与朝向始终为有限数值。

### 6.3 暂停和恢复

状态机：`MENU → RUNNING ↔ PAUSED`，`RUNNING → UPGRADE → RUNNING`，`RUNNING → VICTORY/DEFEAT → MENU或新局`。暂停遮罩由仍可响应的UI处理；不要把整个Phaser Game暂停后又依赖其已暂停输入恢复。

用暂停原因集合处理 `manual / hidden / portrait / performance`，升级是独立状态。visibility隐藏、窗口失焦、手机竖屏时冻结仿真，清空输入、累加器和按下缓存；恢复可见/横屏只移除对应原因，仍需点“继续”。升级选择不能清除其他暂停原因，手动继续也不能绕过竖屏遮罩。

恢复时从新帧开始计delta，禁止补算后台时间。音频与仿真一起暂停；纯视觉动画可以继续。所有会影响战斗的计时只能走仿真，不使用setTimeout、setInterval或Scene Timer。

## 7. 攻击事件、碰撞与统一伤害

### 7.1 真人射击

每到可射击tick，在650范围内选最近存活且已激活的敌人；没有目标则不生成事件、不开始枪冷却。计算该瞬间的方向，在真人中心沿方向前移18单位作为枪口，夹取到场内。

攻击提交是一次事务：录制容量与弹丸容量都允许 → 创建弹丸并记录相同快照 → 更新冷却。容量不足则不创建、不录制、不消耗冷却，并增加拒绝计数。记录事件表示“确实发射”，不表示“确实命中”。

分身回放时使用记录的枪口、角度、速度、半径、寿命和伤害。原目标已死亡或远离，也照旧开火；新敌人进入历史弹道则可被击中。普通子弹不追踪、不重选目标。

### 7.2 子弹连续碰撞

只判断“新位置是否落进敌人圆内”会漏过高速子弹。每步保留弹丸 `p0 → p1` 与目标中心 `e0 → e1`，使用相对运动：`r0=p0-e0`，`r1=p1-e1`，对线段 `r0→r1` 与原点半径 `弹丸半径+目标半径` 的圆求最早交点参数u∈[0,1]。

若起点已在圆内，u=0；相对位移为0时单独处理，禁止除0。多个候选取最小u，u相同时按实体ID升序；非穿透弹丸只消耗一次。出界与寿命到期也产生截断参数：只检测实际仍在场内且仍存活的路径，命中点必须不晚于该参数。

新弹丸在本步末姿态发射，创建当步仅检查枪口重叠，下一步才开始位移，避免与目标本步发射前的轨迹发生“逆时间碰撞”。震荡波也以本步末中心做瞬时判定。冲刺本步免伤，分身循环瞬移不参与任何扫掠碰撞。

弹丸创建时 `remainingTicks = ttlTicks`，创建步不减寿命；之后每个飞行步先扫掠再减1，减至0立即回收。因此寿命60 tick代表最多60次飞行步，不会因创建当步扣减而少飞一帧。敌方弹丸使用同一几何与寿命算法，目标换成真人。

敌人接触伤害也用相对运动的圆扫掠判定，两圆半径相加，防止冲锋者一整步穿过真人而漏伤。该步真人处于冲刺时忽略接触与弹丸伤害；冲刺在开始tick起连续9步生效，到下一步再恢复普通移动和受伤资格。

### 7.3 震荡波

创建时以 `distance(enemyCenter, origin) <= radius + enemyRadius` 判断，当前范围内每个活跃敌人一次伤害。伤害判定只执行一次，扩散圆环只是视觉效果，不能每个渲染帧重新结算。首版无击退、眩晕、持续伤害、弹丸反弹。

### 7.4 统一去重与结算

- 所有攻击实例ID一局唯一；同实例和同目标的命中键为 `(attackId, targetId)`。
- 子弹命中立即置为spent；范围攻击使用本次受击集合，结算后随实例释放，不保留全局永久Set。
- 一条回放事件的触发身份为 `(echoId, loopSerial, eventSeq)`。事件游标每步只前进一次；下一轮合法重播获得新attackId，不被上一轮去重误杀。
- 同tick多个攻击可以一起伤害同一敌人；按attackId升序结算，HP第一次降至0时产生唯一死亡事件。之后的候选不重复给分；子弹若已在本步选中该目标，仍被消耗，不临时改选穿透目标。
- 真人同时收到多来源伤害，筛出有效命中后取最高值；相同伤害按来源ID决胜。冲刺或受伤保护期间取0，成功受伤后设保护截止tick。
- 同一个敌方弹丸碰到真人后，无论是否因免伤而伤害为0，都立即消费。碰撞外的弹丸照常飞行。
- 敌人死亡不掉实体经验球，直接加击杀和分数。伤害统计记实际扣除HP，不累计过量伤害。

### 7.5 来源和容量优先级

友方弹丸调度顺序固定为：真人 → 分身按clip从新到旧；同一来源按事件seq。上限不会因数组迭代顺序不同随机吞掉真人攻击。分身事件若因上限被拒绝，本轮该次跳过、不重试、不改变clip；开发面板显示次数。

初值下普通枪最多每秒5发、弹丸寿命1秒，四个攻击源约20枚在途弹丸，240的上限留有明显余量。正式验收要求基准场景拒绝次数为0。对象池不足不能静默改变命中规则。

## 8. 敌人、波次与策略交互

### 8.1 三种敌人

| 敌人 | 参数起点 | 状态与行为 | 对分身玩法的作用 |
| --- | --- | --- | --- |
| 追击者 | HP30，半径16，速度105，接触伤害10 | 追踪真人当前中心，进入接触范围后受全局受伤保护限制 | 可被玩家牵引进旧弹道；不追分身 |
| 冲锋者 | HP50，半径20，常速65，接触伤害18 | 接近到420内后预警36 tick，锁定方向，冲锋24 tick/速度480，再恢复90 tick | 锁方向后玩家横移，让冲锋者穿过分身火线 |
| 射击者 | HP40，半径17，速度75，弹伤8 | 保持260～340距离；每90 tick瞄准真人一次，预警24 tick后按锁定方向发弹 | 迫使玩家换位，防止把所有历史轨迹叠在角落 |

冲锋者按状态进入时锁定方向，不在冲锋中追踪；敌人冲锋触边立刻结束。射击者每轮最多一发，弹速260、半径5、寿命180 tick，不打分身、不伤敌人。敌方预警和射击方向可以被真人走位骗开。

敌人只感知真人；分身既不能吸子弹也不能替真人挡伤害。敌人对分身伤害无额外抗性。首版不引入破盾、弱点、元素和仇恨列表。

### 8.2 出生强度

| 时间 | 出生间隔 | 敌人权重 | 目的 |
| --- | --- | --- | --- |
| 0～18秒 | 60 tick | 追击100% | 学会第一轮分身 |
| 18～60秒 | 45 tick | 追击80%、冲锋20% | 学会引怪 |
| 60～120秒 | 36 tick | 追击60%、冲锋25%、射击15% | 打破站桩 |
| 120～180秒 | 30 tick | 追击50%、冲锋30%、射击20% | 验证更新轨迹与技能节奏 |

开局可立即预约首个出生预警。波次由仿真tick驱动，不用真实时间。随机数使用局内有种子的PRNG，便于复现；序列一致不等于跨浏览器浮点结果完全相同。

暂不增加敌人HP倍率；先调生成间隔和速度。达到70上限后跳过出生，不在玩家清场后瞬间补几十个敌人。敌人不出战场、不在UI按钮处另加隐藏伤害规则。

### 8.3 防止退化玩法

旧轨迹只能保留三段，玩家不能永久经营同一火力阵；远程与冲锋预警促使换位。若角落站桩明显强于移动，先查看生成分布与敌人射击，不直接加入无提示的强制伤害。若分身命中率很低，先检查弹道可视性和引怪体验，再调弹速、敌人速度或0.45系数。

## 9. 技能和升级兼容规则

### 9.1 兼容矩阵

| 能力 | 真人规则 | 记录内容 | 分身重演 | 首版限制 |
| --- | --- | --- | --- | --- |
| 基础枪 | 自动选当前目标 | 世界枪口、方向、攻击参数 | 原方向发新子弹，伤害×0.45 | 无追踪、穿透、暴击 |
| 冲刺 | 短距离快速移动并免伤 | 每tick实际pose与dashing | 轨迹与残影；分身本身已不可受伤 | 无冲刺伤害、无碰撞推开 |
| 震荡波 | 按Q瞬时范围伤害 | 原中心、半径、伤害 | 在旧位置范围结算，伤害×0.45 | 无击退、无DOT |
| 枪伤升级 | 伤害+3，可选2次 | 后续事件写新伤害 | 已封存clip不变 | 不追溯修改 |
| 移速升级 | 速度+10%，可选2次 | 后续实际位置变化 | 按录制轨迹走 | 不再乘分身移速 |
| 震荡扩容 | 半径+20，可选2次 | 后续事件写新半径 | 使用快照半径 | 不改变历史范围 |

60秒、120秒在全部6秒边界处理完成后，暂停展示上述三个固定候选；每次选一个。恰好两次选择，无随机卡池、刷新、稀有度或永久成长。旧clip保留升级前火力，新纪录逐步替换，形成18秒内的自然更新过程。

冲刺与震荡波冷却不会因6秒边界、升级或分身生成重置。选择升级不回血；首版不设置回血升级，便于验证存活压力。

### 9.2 未来增加技能必须回答的五个问题

1. 输入意图和成功施放怎样区分？事件在什么时候写入？
2. 哪些参数要快照？哪些数据需要当前世界查询？
3. 同一攻击对同一敌人能命中几次？生命周期如何结束？

### 10.3 渲染与释放

画面在上一/当前仿真姿态间插值，伤害总用仿真状态。分身循环跳点、新出生、重开使用teleport标记，前后姿态一起重置，禁止插值横穿场地。角度插值使用最短弧。

ArenaScene关闭时解绑键盘、pointer、resize、visibility监听，释放显示对象映射与音频引用。重开创建新World，重置全部实体、clip、tick、PRNG、输入和暂停状态；只保留设置与本地最高分。

## 11. 手机横屏、浏览器和视觉预算

使用固定逻辑画布1280×720，Phaser Scale FIT + CENTER_BOTH，使宽高比不同设备留边且战场范围一致。该缩放模式和居中配置可参照[Phaser Scale Manager文档](https://docs.phaser.io/phaser/concepts/scale-manager)。

页面背景填满可视窗口，游戏画面在其中完整显示。HUD不能跟着浏览器宽高改变世界坐标；缩放后输入必须转换到统一逻辑坐标。Phaser提供统一键鼠/触摸事件，可参照[输入文档](https://docs.phaser.io/phaser/concepts/input)，但多指绑定、取消与释放仍需自行设计并验收。

- 左侧固定摇杆区域；手指开始后按pointerId绑定，移出区域仍归原摇杆，松开/取消恢复0。
- 右侧两个技能按钮各绑定独立pointerId；至少支持移动+技能两指操作，测试三指和手指交叉。
- DOM按钮按实际CSS尺寸至少48×48px，间距至少8px；若用Canvas按钮，必须按缩放后的CSS尺寸检查，不能只看逻辑像素。
- 游戏容器设置合适的 `touch-action: none`，防止滚动和缩放；页面其他区域不无差别屏蔽交互。
- 处理pointerupoutside、pointercancel、blur、resize；发生失焦或方向变化时清空所有绑定，防止持续跑动。
- 使用safe-area-inset避开刘海和底部手势区；验收390×844与360×800竖屏，以及对应横屏。
- 竖屏遮罩显示“请横屏后继续”，冻结战斗；不强制依赖方向锁定API。全屏是用户点击触发的可选功能，失败仍可玩。
- 首次点击开始后才能启动音频；音乐/音效默认适中，静音设置可保存。音频创建失败不阻断游戏。
- 基准DPR先限制为不超过2，若性能不足降至1；不改变逻辑坐标。

目标浏览器：当前桌面Chrome/Edge、Android Chrome、iOS Safari。浏览器模拟不能代替真机多点触控与音频检查。

性能目标为待实测指标：选定并记录一台真实手机，在70敌人、约40友方弹丸、120敌方弹丸的压力场景下运行60秒，稳定30FPS以上；桌面目标60FPS。另测强制满容量360弹丸的极限夹具。每项记录设备、系统、浏览器、构建版本、平均/低分位帧率、仿真耗时和容量拒绝计数。

首版遍历子弹与敌人即可；只有实测核心碰撞耗时超过预算，再加均匀网格候选筛选，并保留同一几何测试。性能优化顺序：限制特效 → 复用高频显示对象 → 空间网格，避免先写复杂对象池和ECS。

## 12. 难点、漏洞与防护

| 风险 | 典型错误 | 固定策略 / 必测点 |
| --- | --- | --- |
| 回放漂移 | 直接按键重演、每显示帧移动 | 固定步与姿态样本；30/60/120Hz一致性 |
| 边界重复 | 生成时放一次，第0步再放一次 | 新分身下一步才执行事件；359/0边界测试 |
| 分身指数增长 | 所有攻击都写Recorder | 仅真人成功攻击可写；来源断言 |
| 冷却刷新 | 每6秒重置技能 | 使用绝对tick；跨边界剩余冷却断言 |
| 历史被升级污染 | clip保存同一属性对象引用 | 快照复制、开发冻结；升级后旧clip相等 |
| 伤害连乘 | 每层都乘0.45 | 仅AttackFactory转换一次 |
| 多帧伤害 | 扩散圈持续overlap | 瞬时范围攻击；每目标一次 |
| 高速穿透 | 仅测新位置 | 相对运动线段-圆；测试切线、起点重叠、零位移 |
| 边界瞬移伤害 | 分身终点扫回起点 | 分身无接触伤害；teleport不扫掠、不插值 |
| 淘汰后报错 | 子弹引用已销毁分身 | 实例自含参数；TTL独立；无活对象引用 |
| 暂停追赶 | 后台回来补几十秒 | 清累加器、冻结tick、显式继续 |
| 输入粘住 | 触摸取消未清零 | pointerId绑定与取消路径测试 |
| 无限刷怪 | 上限后累计补刷 | 跳过预约，不积债 |
| 内存增长 | 命中Set/监听器永不释放 | 短期Set，场景清理，重开20次后计数检查 |
| 无效几何 | NaN方向、零距离归一化 | 有限数检查，零向量回退，半径/TTL上下界 |
| 本地分数作弊 | 把localStorage当可信排行 | 仅本机娱乐记录，不做可信在线竞争 |

设置和最高分通过带版本号的localStorage键保存；解析失败、隐私模式写入失败时回退默认值。不得把API密钥写入VITE变量；本游戏不需要任何密钥。

## 23. M9：GitHub与Render静态发布

依赖：M8。工作量起点：半天～1天。

GitHub用于源码托管，Render Static Site用于主要访问网址。GitHub Pages是可选第二发布目标，不属于首版必做项。Vite构建默认输出dist；官方说明preview仅用于本地预览，[Vite静态部署文档](https://vite.dev/guide/static-deploy.html)给出了Render与GitHub Pages路径配置。

### 23.1 Render字段

| 字段 | 设置 |
| --- | --- |
| New服务类型 | Static Site |
| Repository | 实际GitHub仓库 |
| Branch | 实际发布分支，默认main |
| Root Directory | package.json所在目录；仓库根目录则留空 |
| Build Command | `npm ci --include=dev && npm run typecheck && npm test && npm run build` |
| Publish Directory | `dist` |
| Start Command | 不需要 |
| Node版本 | 与M0锁定版本一致 |

只使用首页内状态，不引入浏览器history路由，因此首版无需SPA重写配置。静态资源从仓库发布，不配置CORS代理。Render的建站入口与Git集成见[Static Sites官方说明](https://render.com/docs/static-sites)；字段含义见[首次部署文档](https://render.com/docs/your-first-deploy)。

可选 `render.yaml` 基本形态，已按[Render Blueprint参考](https://render.com/docs/blueprint-spec)核对主要字段，M9实施时仍需检查平台变化：

```yaml
services:
  - type: web
    name: echo-rush
    runtime: static
    buildCommand: npm ci --include=dev && npm run typecheck && npm test && npm run build
    staticPublishPath: ./dist
```

这里 `type: web` 配合 `runtime: static` 表达静态站点，不能据此去控制台误建Node Web Service。不添加端口、启动脚本或数据库。

### 23.2 资源路径

Render根路径部署用Vite默认 `base: '/'`。Phaser运行时加载public资源时使用 `import.meta.env.BASE_URL + 'assets/...'`，不要手写本机盘符；文件大小写与仓库一致。

若以后同时启用GitHub Pages仓库子路径，单独构建 `base: '/echo-rush/'` 并验证资源请求。不要把Pages子路径产物直接用于Render根网址。Vite对构建资源路径的说明见[官方构建文档](https://vite.dev/guide/build.html#public-base-path)。

### 24.2 可复现核心夹具

固定出生种子，禁用随机刷怪，玩家从 `(300,300)` 开始。输入轨迹为90tick向右、90tick向下、90tick向左、90tick向上；速度230，总位移理论上回到起点，逐样本与录制比较使用容差。

在夹具中通过测试专用入口提交tick0、tick359攻击，其他自动攻击关闭。让目标在录制后换位，验证“样本与发射参数相同，最终伤害对象可以不同”。夹具构造事件必须走同一个校验/工厂接口，不直接伪造DamageSystem输出。

另建跨边界弹丸夹具：tick359在靠近场地中央发射，飞行目标距枪口足够远；边界淘汰来源分身后，弹丸在下一轮实际击中目标。不能用刚发射就重叠的目标冒充在途验证。

### 24.4 长时与性能

自动仿真10分钟可以在测试模式下延长局时，用于暴露生命周期问题，不改变正式180秒配置。记录每360tick的clip数、pose总数、攻击数和回收数，稳态必须有界。浏览器堆内存会受GC影响，不要求每秒单调下降；重点是存活对象数量与多次稳定后是否持续增长。

性能测试不可用只跑核心的Node耗时代替手机画面帧率。Playwright模拟手机视口只能检验布局和部分事件，不能证明移动GPU、真实多点触控、Safari音频策略均正常。

## 25. 调试面板与统计定义

开发模式显示：completedTicks、localTick、当前状态/暂停原因、clip队列、各分身loopSerial/eventCursor、敌人/弹丸/特效数、拒绝次数、最近命中来源、仿真耗时。

| 指标 | 定义 |
| --- | --- |
| 真人伤害 | source.kind为player的实际HP扣除总和 |
| 分身伤害 | source.kind为echo的实际HP扣除总和 |
| 分身伤害占比 | 分身伤害 /（真人伤害+分身伤害）；总和0时显示“—” |
| 分身子弹命中率 | 命中敌人的分身子弹数 / 已实际生成分身子弹数；范围技能排除 |
| 拒绝次数 | 因容量、事件上限而未生成的攻击数量，分来源记录 |
| 存活时间 | completedTicks / 60；暂停与后台时间排除 |

子弹命中率统计按一局发射队列跟踪，结算时仍在飞行的子弹计入分母并标注“含未落地弹丸”；调参对比也可另记只含已结束生命周期的命中率，但不得混用。分身伤害比例只反映该局输出来源，不代表玩法更优或技术先进。

## 26. 范围控制、止损与可展示成果

开发顺序固定：先时钟与移动，再战斗，再录制，再三分身，再技能，再完整局与发布。M3/M4遇到问题，先用静止木桩与固定命令夹具定位，暂时关闭随机刷怪和特效。

如时间不足，优先延后射击者和第二次升级，但在docs/decisions.md说明最终范围变化；核心的6秒、3分身、统一伤害、PC/手机和静态部署不能靠模糊描述跳过。不得把裁剪后的版本标为本文所有验收均通过。

可展示材料在实际完成后采集：一段30～60秒PC/手机录像，一张模块图，359/360与FIFO边界测试结果，真实设备性能记录，GitHub仓库与公开试玩网址。项目说明可以写“实现固定步长动作快照、事件回放和最多三分身的有界循环，完成跨平台浏览器适配与静态部署”；性能和测试数字必须从实际记录填写。
